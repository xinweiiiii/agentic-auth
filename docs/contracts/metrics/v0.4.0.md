# Contract — Metrics (0.4.0)

New metrics for the MCP OAuth 2.1 baseline (feature 011), following the existing naming in
`agentic_auth/services/metrics.py` (`agentic_auth_*`, Prometheus, built into
`ControlPlaneMetrics` and exposed at `/metrics`).

## 1. Control plane

| Metric | Type | Labels | Meaning |
|---|---|---|---|
| `agentic_auth_consent_refusals` | Counter | `reason` | Consent requests refused before any session existed. `reason` is `subject_token_required` \| `subject_token_invalid` \| `subject_mismatch` \| `idp_unavailable` \| `client_not_authorized`. These refusals have no audit row (there is no session to attach one to), so this counter and a log line carrying the token's fingerprint are their only record. |

## 2. Enforcement points

A connector proxy or gateway with `AGENTIC_AUTH_GATEWAY_OAUTH_RESOURCE_ENABLED` adds no metric
family. A refused inbound token is counted on the gateway's existing decision counter with
`outcome="blocked_local"` (or `blocked_infra` when the IdP's keys could not be obtained) and a
`reason` of `TOKEN_MISSING`, `TOKEN_IN_QUERY`, `INVALID_TOKEN`, `INSUFFICIENT_SCOPE` or
`IDP_UNAVAILABLE`, and recorded in the edge trace the same way.

## What labels never carry

- No token, no token fragment, no token fingerprint.
- No `client_id` and no subject: unbounded cardinality, and both are identities, which belong in
  the audit trail behind the audit-reader check.

`reason` is a bounded enum.
